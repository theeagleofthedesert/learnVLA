# notes/06 失败分类：π0.5 在 LIBERO 上到底怎么失败的

> 读者：lwang。目的：成功率是一个数，失败视频才是信息。这份笔记教你怎么系统地看失败、怎么给失败起名字，以及这些名字对"下一步该做什么"意味着什么。

## 1. 先记住一个机制：LIBERO 没有"中途判负"

`eval_libero.py` 的循环只在两种情况下结束：`done`（BDDL 目标谓词全满足）或跑到 `max_steps`。
所以 **每一条失败的 `steps` 都等于 suite 的 max_steps**（220/280/300/520），`steps` 列对失败没有信息量。
"失败"的真正含义是"在限定步数内没有达成目标"，不是"做错了什么"。机器人可能一直在尝试，也可能早就卡死了，CSV 分不出来——要看视频。

## 2. 工具：6 帧拼图

每条失败视频 220–520 帧，逐条看太慢。`scripts/contact_sheet.py` 把一条视频等间隔抽 6 帧横向拼成一张图（左 agentview、右 wrist 是视频本身的布局，时间从左到右，左上角标 t）：

```bash
source scripts/env.sh && source $LIBERO_VENV/bin/activate
python scripts/contact_sheet.py results/eval_official/libero_10/videos/*_fail.mp4 --out results/failure_gallery/official
```

6 帧够回答"卡在哪个阶段"；要看具体怎么卡的再开 mp4。

## 3. 分类表

按"任务进行到哪一阶段出的问题"分，而不是按"看起来像什么"分。每一类对应不同的修法。

| 代号 | 名字 | 怎么认 | 对应的修法方向 |
|---|---|---|---|
| A | 接近停滞 (approach stall) | 手一直悬在目标物上方/旁边，始终没有合拢夹爪 | 视觉定位/深度歧义；多视角或 wrist 更关键 |
| B | 抓取失败 (grasp fail) | 夹爪合了，物体没跟着走，或抓起后掉落 | 抓取点学得不好；数据里该物体的抓法单一 |
| C | 放置偏离 (place miss) | 物体松开了，但落在目标区域外（地上、碗沿、篮子边） | 放置精度；替换 replan 看是否改善 |
| D | 悬停不放 (hover, no release) | 物体抓在手里、在目标上方悬停到超时，始终不松 | 多阶段任务里"下一步"的决策卡住；典型的长时程问题 |
| E | 语言/物体混淆 (wrong object or wrong target) | 抓了指令没提的物体，或放到了错误的位置（左右、哪个抽屉） | 语言落地；同场景近邻任务（t0/t7 只差一个物体）最容易出 |
| F | 看似完成但未判成功 (done-looking) | 画面上目标达成了，但 `done` 没触发 | 谓词边界（"in" 要求完全进入篮子、物体叠放不算）；要查 BDDL |
| G | 碰撞/打翻 (knock over) | 把别的物体撞倒、炉台撞歪，后续动作全乱 | 轨迹层面安全；通常伴随 D |

一条视频可以同时标两类（比如先 G 后 D），主类写最早出现的那一个。

## 5. 从分类表能得出什么

- **libero_10 的失败集中在 t8（两只摩卡壶）且大多是 D**：第一只放好后对第二只的放置点犹豫。这是"第二阶段放哪"的决策问题，不是抓取问题。官方 92.4 的失分几乎全在这里。
- **E 类集中在同场景近邻任务**（libero_10 t0/t7、libero_goal 的抽屉系列），说明语言条件在"场景一样、指令只差一个词"时最弱。LIBERO-Plus 的 language 扰动类会放大这一点。
- **C/B 类在 object/spatial 上零星出现**，是运动精度噪声，用 K 次采样（§1.5 随机性实验）能看出这类失败是否可被重采样"洗掉"。
